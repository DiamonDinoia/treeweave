# conda-forge recipe (prep)

`recipe/meta.yaml` builds `treeweave` (the Python package, with its compiled
nanobind/C-ABI extension) for conda. The recipe is ready here, but nobody has submitted
it yet. conda-forge packages live in the external
[`conda-forge/staged-recipes`](https://github.com/conda-forge/staged-recipes)
repo, so the actual submission is a manual follow-up.

## Once the feedstock lands

```sh
conda install -c conda-forge treeweave
```

becomes the one-liner install for conda users. Add a conda-forge badge to the
top-level README then:

```markdown
[![conda-forge](https://img.shields.io/conda/vn/conda-forge/treeweave)](https://anaconda.org/conda-forge/treeweave)
```

## Submitting to staged-recipes

1. Fork and clone `conda-forge/staged-recipes`.
2. Copy `recipe/meta.yaml` to `recipes/treeweave/meta.yaml` in that repo.
3. Confirm `version` + `source.sha256` match the release being submitted
   (the recipe hardcodes the version because staged-recipes only copies the
   recipe directory, and it cannot read this repo's `VERSION`; keep the two in sync).
4. Open a PR; the conda-forge CI builds the recipe on linux/macOS/windows.
5. After merge, an autogenerated `treeweave-feedstock` repo takes over; its
   autotick bot bumps `version`/`sha256` on each new release.

## Local test before submitting

```sh
conda install -n base conda-build      # or: pixi global install rattler-build
conda build conda/recipe               # or: rattler-build build -r conda/recipe/meta.yaml
```

The recipe's `test:` block imports `treeweave` and runs a fit+eval smoke
(exp on `[0, 1)`, max abs error < 1e-8).

## Why not noarch

The package ships a compiled extension (`_treeweave`, nanobind over the
treeweave C ABI), so it is platform- and Python-ABI-specific and cannot be
`noarch: python`. The recipe uses `{{ compiler('cxx') }}` + cmake/ninja in
`build` and scikit-build-core/nanobind/numpy in `host`.
