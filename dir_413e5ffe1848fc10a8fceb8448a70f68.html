Detailed Description

MATLAB and GNU Octave wrapper for the canopy piecewise-Chebyshev function approximator. One source builds for both: Octave (≥ 6) supports passing a function_handle into a MEX and feval-ing it via mexCallMATLABWithTrap, which is exactly the mechanism the trampoline uses — so no Octave-specific gateway is needed.

The binding is generated by mwrap: canopy.mw is the single source of truth, from which mwrap produces the MEX gateway (canopy_mex_gen.cpp) and the per-function bz_*.m stubs. Those generated files are committed (generated-not-hand-edited), so a plain rebuild needs neither mwrap nor flex/bison. The user-facing canopy.m is a thin classdef that stores the opaque canopy_t handle in its mwptr property (mwrap's R2008OO object-pointer convention).

Prerequisites

  • MATLAB R2019b+ (tested on R2025b)
  • libcanopy_c.{a,so} built under ../../build*/ (i.e. cmake .. && cmake --build . in the repo root)
  • mwrap — only to regenerate after editing canopy.mw. Found on PATH, or cloned + built automatically by the CMake glue (plain make; flex/bison are required only to modify mwrap's grammar).

Build

# No MATLAB license needed; -static-libstdc++ keeps the .mexa64 independent of
# MATLAB's bundled libstdc++.
make MATLAB_ROOT=/usr/local/MATLAB/R2025b CANOPY_BUILD=../../build

The mex compiles with -DR2008OO (selects mwrap's classdef/mwptr path).

To regenerate the gateway after editing canopy.mw:

make mwrap_gen MWRAP=/path/to/mwrap # or the CMake `regenerate-matlab` target

Octave

No MATLAB license needed; mkoctfile compiles the same committed gateway against Octave's mex API:

make octave CANOPY_BUILD=../../build # produces canopy_mex.mex

Octave is not shipped as a prebuilt binary (it has no stable MEX ABI across versions) — build from source with the line above. The only Octave-specific piece is octave_compat/matrix.h, an empty shim that satisfies mwrap's #include <matrix.h> (a MATLAB-only header; Octave's mex.h is self-contained). On a host that also has MATLAB, the Makefile drops the MATLAB build's CXXFLAGS for this target so MATLAB's matrix.h can't shadow the shim.

Usage

addpath('/path/to/canopy/bindings/matlab');
% 1-D scalar fit (dim & out_dim inferred)
f = @(x) exp(0.5*x(1)) + sin(3*x(1));
obj = canopy(f, [0], [1], 1e-8);
% Evaluate at N points (N×dim matrix → N×out_dim)
X = linspace(0, 1, 1000)';
Y = obj.eval(X); % or Y = obj(X)
Ys = obj(X, 'sorted', true); % 1-D ascending fast path
% 2-D → 3-D vector fit (out_dim inferred by probing g; degree auto per CPU)
g = @(x) [sin(x(1)+x(2)); cos(x(1)-x(2)); x(1)*x(2)];
obj2 = canopy(g, [-1,-1], [1,1], 1e-6, 'max_memory_mib', 64);
[gx, gy] = meshgrid(linspace(-1,1,50));
Y2 = obj2([gx(:), gy(:)]); % 2500×3
Yt = obj2([gx(:), gy(:)], 'transposed', true); % 3×2500 (struct-of-arrays)
fprintf('Memory: %.1f KiB\n', obj2.memory_usage()/1024);
delete(obj2);

Trampoline design

canopy_fit accepts a C callback void f(const double *x, double *y, void *context) invoked once per Chebyshev sample (synchronously, many times, before returning). The leaf degree is auto-selected by the C ABI for the detected CPU; accuracy is driven by tol. To call a MATLAB function_handle from inside this callback (the C side receives it via mwrap's mxArray pass-through, stashed in the context pointer):

  1. A TrampState struct (file-static scope during the fit call) holds the handle, dimensions, and an error flag.
  2. The callback builds a 1×input_dim mxArray, calls the handle via mexCallMATLABWithTrap — the Trap variant returns a non-NULL mxArray* exception instead of longjmp-ing, which would corrupt the C++ canopy call stack.
  3. On exception: stash the mxArray, set errored=1, fill y with NaN, return. All subsequent callback invocations short-circuit with NaN.
  4. After canopy_fit returns: if errored, re-raise the stashed message via mexErrMsgIdAndTxt("canopy:callback", ...). If the fit returned NULL, raise "canopy:fit" with canopy_last_error().

All of this lives in the $[ ... $] inline-C block of canopy.mw.
