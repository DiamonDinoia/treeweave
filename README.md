**Evaluate an expensive function millions of times, fast.**

treeweave fits your function once — building low-order polynomial panels on an adaptive tree — and returns a drop-in replacement accurate to your chosen tolerance. Pay once at fit time; every evaluation afterward is a cheap lookup.

## Why treeweave

- **Fit once, evaluate forever.** Amortize an expensive function into a cheap polynomial lookup.
- **Adaptive paneling.** Low-order panels on an adaptive tree reach tolerance at lower order than a global fit — SIMD-friendly.
- **Seven languages, one core.** A stable C ABI (`libtreeweave_c`) underpins Python, Julia, MATLAB/Octave, Fortran, and JavaScript/TypeScript; C++ is header-only.
- **Thread-safe by construction.** A fitted object is immutable; `operator()` is safe to call concurrently.

## Quick start

```cpp
#include <treeweave/treeweave.hpp>
#include <cmath>

// zeta_N(s) = sum_{k=1..1000} k^-s — hundreds of pow() calls per evaluation.
auto zeta = [](double s) {
    double a = 0.0;
    for (int k = 1; k <= 1000; ++k)
        a += std::pow(k, -s);
    return a;
};

// Fit once (milliseconds); f is then a cheap polynomial good to ~1e-10.
auto f = treeweave::fit(zeta, 2.0, 10.0, /*tol=*/1e-10);

double y = f(3.5);   // evaluate the polynomial, not the original function
```

## Domain contract

The fit domain is `[a, b)`. Evaluating exactly at `b` returns the boundary value (the last panel's polynomial). Every other out-of-domain point — below `a`, above `b`, `NaN`/±Inf — returns `NaN` on all eval paths, branchless.

## Limitations

- May use a lot of memory on oscillatory or rapidly-varying functions; fit one period if periodic.
- Cannot fit through a singularity — shift the domain or use multiple fits around it.
- No input bounds checking.
